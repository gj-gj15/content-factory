# 07 分发（publish）

> 取材自 `content-distribution-team/1.0.1/skills/multi-platform-distribution/references/`（platform-publishing-rules / scheduling-strategy / account-management-guide）。
> ⚠️ 该团**包内零行发布代码**（空壳④），所有"API 自动发布"都是规格文档，没有实现。
> 本环境做法：**保存草稿 + 手动发布**，或你后续接 OAuth 后再自动。下面给的是可直接照做的规则。

## 1. 平台能力矩阵（决定自动 or 手动）
| 平台 | 发布方式 | 内容元数据必填 |
|------|---------|---------------|
| YouTube/TikTok/FB/IG/X/Pinterest/快手/B站 | 规格说 API 自动 | title/description/medias/platform |
| 小红书/抖音/视频号 | ⚠️ 草稿→手动 | 同上，但需你到 App 点发布 |

## 2. 内容元数据标准（每次发布准备）
必填：`title`(≤100字) / `description`(平台适配) / `medias`(≥1个URL) / `platform`
可选：`tags`(5-15) / `topics`(分区) / `coverUrl` / `publishTime` / `accountId`
账号标识格式：`[平台类型] 账号名称 (id: xxx)`，如 `[YOUTUBE] my_channel (id: 789)`

## 3. 排期最佳时间（国内主力）
| 平台 | 工作日最佳 | 周末最佳 |
|------|-----------|---------|
| 抖音 | 20:00-21:00 | 20:00-21:00 |
| 小红书 | 20:00-22:00 | 15:00-17:00（周二~周四更好） |
| B站 | 20:00-22:00 | 16:00-18:00 |
| 公众号 | 8:00 | 8:00 |
| 视频号 | 19:00-21:00 | 19:00-21:00 |

策略：错峰发布（主力平台先发→次要从后跟）；梯度发布（核心 1-2 平台先发看数据，24h 内扩）。

## 产物（v2.2：按平台中文文件夹组织，见 `references/delivery-spec.md`）
每个平台的成稿/成片放进该平台的**中文文件夹**，文件名用中文：

```
outputs/<topic>/
├── 公众号/     公众号-主稿.md、公众号-摘要标签.txt
├── 小红书/     小红书-笔记.md、小红书-封面.png
├── 抖音/       抖音-成片.mp4、抖音-发布说明.md
├── 视频号/     视频号-成片.mp4、视频号-发布说明.md
├── B站/        B站-成片.mp4、B站-发布说明.md
└── 汇总/       发布清单.md（平台/账号/标题/定时/状态 + 回执）
```

交付时给清单表：`平台 | 文件中文名 | 绝对路径 | 状态`。**禁止用英文/拼音文件名交付**（内部中间产物可留英文）。
