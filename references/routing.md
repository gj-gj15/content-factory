# 通道决策树（总控专用）

对每个新选题，按以下信号路由：

| 用户目标信号 | 路由 | 备注 |
|---|---|---|
| 出镜 / 成片 / 短视频 / 口播 / 视频号 / 抖音 / B站 / 带货视频 | **视频通道** | 唯一硬伤=成片需视频API，无则人工拍剪降级 |
| 图文 / 公众号推文 / 小红书笔记 / 纯文字种草 / 朋友圈文案 / 销售话术 | **文案通道** | 零硬依赖，推送到草稿箱需公众号凭证（可手动） |
| 同一选题既要视频又要图文（矩阵分发） | **双线并行** | 先跑文案通道定稿，视频通道复用其脚本结构 |
| 信息不足、无法判断 | **总控问 1 个关键问题** | 例："这条内容主要发在哪？视频还是图文？" |

## 决策原则
- 不确定时**先跑文案通道**验证选题能不能打——它零依赖、最快出结果，跑通后再决定是否投入视频通道。
- 视频通道若因缺 API 阻塞，明确告诉用户"卡在成片"，不要编造成片已生成。
- 双线并行时，两通道共用 `04-design` 产出的 `core-copy.md`（共享母体），再各自加工，不再各写各的。

## 双用 / 双向互转（一份文案两边用）
- 任何选题要出双形态：先令任一通道产 `core-copy.md`，再并行派两通道基于**同一份** core-copy 加工（互为副本，不直连）。
- 已完成文案通道 → 要视频：总控触发"从 `wechat-draft`/`xhs-note` 反推 core-copy → 视频通道生成 `script-final`"。
- 已完成视频通道 → 要图文：总控触发"从 `script-final` 反推 core-copy → 文案通道生成 `wechat-draft`/`xhs-note`"。
- 反推规则见 `dual-use.md`。不变量：子智能体永不互读对方形态化产物，只经 core-copy 中转（符合铁律）。
