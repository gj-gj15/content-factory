# 交付规范（delivery-spec，v2.2 新增）

> 双通道共用。**所有交付给用户的最终产物**都按本规范组织与命名。
> 中间产物可保留英文名，**对外交付一律中文**。

## 1. 必须给真实绝对路径（铁律）
任何交付（成稿 / 脚本 / 钩子资料 / 成片 / 分发清单 / 数据回填）呈现给用户时，必须附**真实绝对磁盘路径**，不许只写相对路径、不许只说"已生成"。

- ✅ 正确：`C:\Users\Administrator\.workbuddy\plugins\marketplaces\my-experts\plugins\content-factory\outputs\opc-one-person-company\公众号\公众号-主稿-v2.2.md`
- ❌ 错误：`outputs/<topic>/wechat-draft.md`
- 用户要能直接复制路径去找文件。

## 2. 按平台中文文件夹组织
多平台产物不堆一锅，按平台分**中文文件夹**：

```
outputs/<topic>/
├── 公众号/
├── 小红书/
├── 抖音/
├── 视频号/
├── B站/
├── 快手/
├── 知乎/
└── 汇总/          ← 跨平台清单、钩子资料、数据回填
```

每个平台文件夹内只放该平台的成稿 / 封面 / 视频 / 发布说明。

## 3. 文件中文命名
- 禁用拼音 / 英文 / 技术命名对外交付（内部中间产物可留英文，交付时改中文）
- 命名规范：`<平台>-<类型>-<版本>.<ext>`
  - `公众号-主稿-v2.2.md`
  - `小红书-笔记.md`
  - `抖音-成片.mp4`
  - `封面-九倍增长对比图.png`
  - `公众号-摘要标签.txt`
- 同平台多份加序号或版本：`小红书-笔记-01.md`

## 4. 交付清单（每次交付收尾必给）
一张表：`平台 | 文件中文名 | 绝对路径 | 状态`。让用户一眼找到每样东西在哪。
